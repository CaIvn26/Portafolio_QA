Validate the complete checkout flow of a simulated e-commerce platform — from adding items to cart through payment confirmation — covering happy paths, error states, field validation, and boundary conditions. Out of scope: payment gateway internals, mobile native app.

Bugs Found
  • HIGH  Dual coupon stacking: Applying two promo codes in sequence applies both, resulting in orders with negative totals. No server-side coupon uniqueness check.
  • HIGH  Negative quantity via URL: Setting ?qty=-3 reduces cart total. No server-side quantity validation.
  • MED  Missing field error messages: Empty shipping fields — form fails silently with no user feedback.
  • MED  Stale stock state: Purchase completes for items that went out of stock mid-session. No revalidation at checkout.
Identified 2 high-severity business logic flaws with direct financial impact. All 4 bugs documented with reproduction steps, expected vs. actual, and severity rationale — ready for dev handoff. Coverage: 8 test cases across positive, negative, edge, and boundary categories.
REST API — User Auth & Task Management
Project URL github.com/your-github/qa-api-task-management ↗
Type Simulated — API testing exercise
Technologies API Testing Auth Validation Postman JWT.io Jira REST JSON
Test Cases 9 cases · 4 bugs found · 1 critical security finding
Objective & Scope

Validate the REST API of a simulated task management application — covering user registration, login/logout, JWT authentication, and full CRUD operations on task resources. Focused on authentication flow integrity, proper HTTP status codes, error handling, and response body structure. Out of scope: performance/load testing, third-party integrations.

Endpoints Tested
POST /auth/register POST /auth/login GET /tasks POST /tasks PUT /tasks/:id DELETE /tasks/:id
Responsibilities
  • Built a Postman collection with 9 test cases covering all auth and CRUD endpoints
  • Detected a critical IDOR vulnerability — unauthorized cross-user task deletion with no ownership check
  • Verified JWT expiry handling and found server-side token validation was entirely absent
  • Documented all bugs with HTTP request/response evidence and OWASP references
  • Flagged inconsistent error response contracts across endpoints

Bugs Found
  • CRITICAL  IDOR — Broken Object Level Authorization: User B can delete User A's tasks by knowing the task ID. Returns 200 instead of 403. No ownership validation on DELETE /tasks/:id.
  • HIGH  Expired JWT accepted: Manually expired tokens (past exp) return 200. JWT expiry not validated server-side.
  • MED  Duplicate registration returns 200: Re-registering an existing email creates a second user silently instead of returning 409 Conflict.
  • LOW  Inconsistent error shape: Some endpoints return {error}, others {message}. No unified error contract.
Caught a critical IDOR vulnerability and a complete JWT expiry bypass — both security findings, not just functional bugs. All bugs documented with HTTP evidence, reproduction steps, and OWASP references where applicable.
